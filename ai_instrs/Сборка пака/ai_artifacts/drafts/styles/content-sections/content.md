## Формат разделов и типы данных

Оформляй разделы инструкции в виде жирного заголовка с двоеточием:
```md
**<Название раздела>:** <Содержимое>
```

### Базовые типы содержимого

- **`Descr` (описание):** простой текстовый блок или одна строка без маркера списка.
- **`List` (список):** маркированный список элементов (`- <элемент>`).
- **`Puncts` (пункты):** одиночный пункт в формате `Descr` либо группа пунктов в формате `List`.

## Стандартные разделы

### 1. Входные данные
Содержит исходные аргументы, параметры и информацию, необходимые для выполнения задачи.
**Формат:**
```md
**Входные данные:**
- `аргумент` — описание аргумента
```

### 2. Выходные данные
Содержит конкретные целевые артефакты, создаваемые файлы или пути сохранения результатов (в отличие от формата вывода, фиксирует реальный артефакт в файловой системе).
**Формат:**
```md
**Выходные данные:**
- `путь/к/файлу` — описание артефакта
```

### 3. Композиция «Вход/выход»
Используй для этапов с явным преобразованием входных данных в результат:
```md
**Входные данные:**
- `<аргумент> — <описание>`

<Инструкции | Алгоритм | Требования>

**Выходные данные:**
- `<артефакт> — <описание>`
```

### 4. Инструкции
Содержит прямые директивы и указания агенту к действию. Тип содержимого — `Puncts`.
**Формат:**
```md
**Инструкции:**
- <Указание к действию>
- <Указание к действию>
```

### 5. Алгоритм
Содержит пошаговую последовательность действий для реализации задачи. Тип содержимого — `Puncts`.
**Формат:**
```md
**Алгоритм:**
- <Шаг 1>
- <Шаг 2>
```

### 6. Задача
Кратко формулирует конкретное действие или цель этапа. Тип содержимого — `Descr`.
**Формат:**
```md
**Задача:** <текст задачи>
```

### 7. Требования
Фиксирует технические ограничения, правила и критерии выполнения. Тип содержимого — `List`.
**Формат:**
```md
**Требования:**
- <Требование 1>
- <Требование 2>
```

### 8. Формат вывода
Описывает структуру и форму ожидаемого ответа агента (сообщение, JSON и т.д.). Тип содержимого — `List`.
**Формат:**
```md
**Формат вывода:**
- <Описание структуры ответа>
```

## Алгоритм оформления разделов

1. Определи необходимые для этапа разделы (все разделы опциональны, включай только нужные для контекста).
2. При наличии входных параметров и сохраняемых файлов используй шаблон «Вход/выход».
3. Для описания шагов выбери «Инструкции» (набор прямых директив), «Алгоритм» (последовательность действий) или краткую «Задачу».
4. Добавь разделы «Требования» и «Формат вывода» при наличии специальных ограничений или ожиданий по форме ответа.
5. Соблюдай синтаксис `**<Название>:**` и соответствующий тип данных (`Descr`, `List` или `Puncts`).
